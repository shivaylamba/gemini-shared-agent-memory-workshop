# Architecture

Four layers. The custom harness is **one** participant interface, not a required intermediary.

```text
1. Participant interfaces   Antigravity │ Claude Code / Codex / other MCP agents │ workshop harness │ replay runner
2. Model access             Google sign-in │ agent's own │ AI SDK: Gemini, OpenAI, Anthropic, OpenRouter, compatible, Ollama │ none
3. Shared knowledge         OpenLore 0.8.0 over MCP (Streamable HTTP) or the JSON API, one token per identity
4. Common app + evaluation  core-app snapshot → workspace → visible tests + hidden grader → runs/<id>/ artifacts
```

## Shared knowledge: OpenLore (verified integration)

OpenLore serves a folder of Markdown as a virtual filesystem. Agents use familiar commands (`ls`,
`cat`, `grep`, `find`, `lore meta`) in a restricted, pure-Go shell, with no host process execution.

| Contract used by the workshop | Where verified |
|---|---|
| MCP over Streamable HTTP at `/mcp`. Tools: `lore_bash { command }` and `list_commands`. Result: `structuredContent { stdout, stderr, exit_code }`. | `agent-harness/tests/openlore.integration.test.ts` against the real binary |
| `mcp.require_auth: true` plus a `tokens` issuer means requests without a token get **401** | same |
| `openlore token mint --identity X --scope read\|full --ttl …` | same, and `scripts/lib/openlore.ts` |
| Docset grants: `ro`, `publish` (inbox only), `rw` | same |
| `publish /proposals/<slug>.md` routes into `/proposals/inbox/`; heredocs keep `$` and backticks literal | same |
| `mv` from the inbox to `/knowledge` as `maintainer`; `lore history` follows the move and keeps the original author | same |
| `lore meta <dir>` (frontmatter as NDJSON); `lore meta set <file> key=value` (one pair per call) | same, and the E2E run |
| Analytics event log: `doc.read`, `search.query`, `doc.hit` per identity | same. **The log format is not a documented API**; the workshop treats a missing log as "unavailable". |

### Policy (`.workshop/openlore/lore.json`, generated by `buildLoreJson()`)

| Docset | Path | `reader` | `contributor` | `maintainer` |
|---|---|---|---|---|
| `knowledge` | `/knowledge` | ro | ro | rw |
| `proposals` | `/proposals` (inbox `inbox`) | none (invisible) | publish | rw |

Identities: `<agent>-capture` (contributor) and `<agent>-reader` (reader) for `harness`,
`antigravity`, `claude-code`, `codex`, `generic` and `partner`, plus `maintainer`. Read-scoped
tokens cannot write, whatever the grants. Keyless SSH is off and unknown keys are denied, so SSH is
effectively closed.

**Limitation:** OpenLore 0.8.0 has no bind-address option. It listens on all interfaces. Every HTTP
request needs a token, but the port is reachable from the network. Tokens expire after 12 hours (4
for pairing). On untrusted networks, keep the one-laptop demo or block the port with a host firewall.

## The harness (`agent-harness/`)

- `agent.ts`: a bounded loop on `generateText` with `stopWhen: [isStepCount(N), toolBudget]`, an
  abort-signal runtime limit, and per-step usage recorded via `onStepEnd`.
- `providers/`: one file per provider; `resolveModelConfig` checks only the chosen provider's credentials.
- `tool-registry.ts`: per-condition toolsets. Baseline and shared-memory share identical local tools;
  shared-memory adds read-only knowledge tools; capture cannot edit code.
- `workspace.ts`: relative paths only; rejects traversal, absolute paths and symlink escapes; denies
  `.env*`, keys, `.git`, `node_modules`, agent configs, and `solutions/`, `recordings/`, `runs/`,
  `evaluation/`. Writes are limited to `src/**.ts` and `tests/**.ts`.
- `tools/`: `list_files`, `read_file`, `search_files`, `write_file`, `run_tests`, `list_knowledge`,
  `search_knowledge`, `read_knowledge`, `propose_knowledge`. Outputs are capped; knowledge results
  carry an "untrusted reference data" note.
- `tracing.ts`: JSONL events, with secrets redacted by value and by shape.
- `run.ts`: every run starts from a fresh copy of the snapshot and passes no history; it writes the
  common artifacts and grades the result.
- `replay.ts`: re-plays a **genuine** recording (refusing synthetic fixtures), applies the recorded
  changes to a fresh snapshot (the hash must match), and re-grades locally.

### Test sandbox

Agent-written code is only executed by `evaluation/sandbox/run-node-tests.ts`:

- `node --permission`: reads only from the workspace copy, writes only to a temp directory; no child
  processes, workers or native addons
- `node --test` with in-process isolation and a JSON reporter
- a scrubbed environment (only `PATH`, `TMPDIR` and explicit variables) and a hard timeout

**Limitations:** the Node 22 permission model does not restrict network access, and it is not an
OS-level sandbox. Grading copies the workspace to a scratch directory and restores the **original**
visible tests, so agents cannot weaken them. The hidden grader is copied next to that copy, never
into an agent workspace.

## External agents

`scripts/lib/external.ts` creates `~/shopflow-workshop/<nn>-<condition>/` (outside the repository)
plus the agent's documented project MCP configuration. Baseline workspaces get none. External agents
are not sandboxed or budgeted by the workshop, so their runs are `controlled: false`.

## Dashboard and replay page (`workshop-ui/`, optional)

A thin layer over the same libraries the CLI uses: `runHarnessFromEnv`, `prepareExternalExercise`,
`collectExternalRun`, the review functions and the evaluation builders. The browser code is plain ES
modules with no framework and no build step.

- `npm run ui` serves the app and a JSON API on `127.0.0.1`, refuses non-localhost `Host` headers,
  requires a per-process token plus JSON for every state change, sends no CORS headers, and never
  returns a credential. Harness runs and replays stream their trace events to the browser over
  server-sent events.
- `npm run ui:static` inlines the same app, its styles, fonts and the data from `recordings/` (plus
  `runs/` with `--include-runs`) into one HTML file. A hash-based CSP allows only its own inline
  script and style and blocks all network access. Synthetic recordings are refused unless
  `--allow-synthetic`, which adds a permanent banner. The build fails if a configured key, or
  anything shaped like a key or bearer token, appears in the page.

## Run artifact format (`evaluation/artifacts.ts`)

```text
runs/<run-id>/
  metadata.json      interface (harness|external), origin (live|replay), controlled, agent, provider/model,
                     condition, OpenLore identity/scope, snapshot hash, prompt hashes, budgets, host
  events.jsonl       trace (harness and replays only)
  result.json        status; correctness (10 checks, regression, 5 constraints); metrics (null + reason if unavailable)
  patch.diff         unified diff against the snapshot
  changes.json       exact changed files (used by replay)
  test-results.json  visible + hidden results
  final-response.md  the agent's final message
  knowledge/         notes read or proposed during the run
```

## Evaluation

- **Experiment A** (`npm run evaluate`): one baseline and one shared-memory run. "Controlled" only if
  interface, agent, provider, model, snapshot, task prompt, budgets and harness version all match.
  Anything else is printed with the differences listed.
- **Experiment B** (`npm run evaluate -- --portability`): producers come from note provenance
  (`proposed_by`, set at review from `lore history`). Consumers are shared-memory runs of any agent
  or model. No performance attribution.
- Capture cost is reported separately. Metrics are never estimated, and bytes are never converted to tokens.
